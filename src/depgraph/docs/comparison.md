# Сравнение с реальным менеджером пакетов (Maven)

Наш инструмент реализует топологическую сортировку (алгоритм Кана), которая гарантирует, что зависимости загружаются раньше тех пакетов, которые от них зависят.

**Возможные расхождения с Maven:**
1. **Mediation (разрешение конфликтов версий):** Maven использует стратегию "nearest wins" (ближайший побеждает). Если два пакета зависят от разных версий одной библиотеки, Maven выберет ту, которая находится ближе к корню графа. Наш инструмент просто собирает все зависимости, не разрешая конфликты версий.
2. **Scope (область видимости):** Maven учитывает `test`, `provided`, `runtime` зависимости. Наш инструмент (на данном этапе) не парсит тег `<scope>` и включает все зависимости подряд.
3. **Порядок объявления:** В Maven порядок загрузки также зависит от порядка объявления в `pom.xml` (при равной глубине). Наш алгоритм сортирует по входящим степеням, что может дать другой порядок для "параллельных" веток.
